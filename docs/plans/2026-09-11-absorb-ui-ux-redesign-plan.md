# ABSORB UI/UX 重新設計計畫書

> 狀態：設計提案，尚未進入實作。  
> 核心受眾：一般投資人優先；每日報告同時服務專業研究者。  
> 核心原則：先讓人看懂，再讓人深挖；所有資訊仍以已驗證資料為準。

## 一、設計目標

ABSORB 不應像塞滿指標的交易終端，也不應像追逐即時話題的新聞網站。重新設計後，使用者應能：

1. 在 5 秒內辨識目前市場、資料日期與資料狀態。
2. 在 30 秒內回答「市場怎麼了、為什麼、要留意什麼」。
3. 從任何摘要一層進入產業、個股或每日報告的完整證據。
4. 清楚區分已發生事實、模型推估、風險限制與資料缺口。
5. 在手機上單手完成市場切換、閱讀摘要與開啟 ASK ABSORB。

## 二、建議方向

採用「雙層研究台」：

- **快速閱讀層**：面向一般投資人，以白話結論、少量關鍵數據、明確資料日期與下一步導覽為主。
- **研究深挖層**：集中在每日報告與明細頁，保留完整證據、反對證據、來源、方法、涵蓋率及限制。
- **共同資料語意**：兩層使用同一份已驗證資料，不另外生成較吸睛但無法追溯的數字。

不建議的方向：

- 純交易儀表板：資訊密度過高，一般投資人難以建立閱讀順序。
- 純新聞動態牆：容易把「新」誤當成「重要」，也會弱化 ABSORB 的證據優勢。
- AI 聊天首頁：將探索責任丟給使用者，且不利於快速掌握整體市場。

## 三、目前介面觀察

本機瀏覽器已檢查首頁、個股、每日報告、學習及 ASK ABSORB：

- 首頁已具備資料日期、涵蓋率、風險、指數與情境資訊，但首屏層級接近，閱讀者需要自行判斷先看哪裡。
- 「市場研究摘要」與「市場指揮台」語意相近，可合併成更清楚的今日摘要。
- 390px 手機版導覽需要水平捲動，後段入口不易被發現。
- ASK ABSORB 的完整頁與浮動面板功能重疊，應明確區分「隨頁追問」與「完整研究對話」。
- 本機每日報告目前呈現不可用狀態，因此計畫保留現有 fail-closed 行為，不把本機缺資料誤判為正式環境內容問題。

## 四、資訊架構

### 主要導覽

保留五個核心入口，命名採使用者語言：

1. 今日
2. 市場
3. 產業
4. 個股
5. 報告

輔助入口：

- ASK ABSORB：保留全站浮動入口與完整頁面。
- 學習：移至「更多」或頁尾知識入口，不與每日決策路徑競爭。
- 台股／美股：維持頂部市場切換，切換後整站內容與連結必須同步市場語境。
- 帳戶：維持工具性入口，不搶占主要閱讀層級。

### 導覽行為

- 桌面：頂部顯示品牌、市場切換及帳戶；左側導覽保持穩定並清楚標示目前頁面。
- 手機：五個核心入口固定可見，不再依賴橫向捲動尋找主要功能；ASK ABSORB 使用獨立觸發器。
- 返回與深入：所有明細頁提供明確上一層，例如「返回產業觀察」而非泛用返回。

## 五、頁面重新設計

### 1. 今日市場

首屏只回答三件事：

- **現在看到哪一天的資料？** 顯示來源交易日、適用交易日與狀態。
- **市場發生什麼？** 使用一段白話摘要及四個以內的關鍵訊號。
- **今天要注意什麼？** 顯示風險、產業焦點及一個明確的深入入口。

建議順序：

1. 市場、日期、狀態列。
2. 今日一句話結論與限制。
3. 指數趨勢、廣度、成交動能、風險四項摘要。
4. 今日焦點事件。
5. 產業與個股入口。
6. 最新盤前／盤後報告。

細節數據以「展開證據」或連往對應頁面呈現，不在首屏平鋪全部資訊。

### 2. 市場實況

- 以指數走勢與市場廣度為主，不把所有數字做成同權重卡片。
- 每張圖表固定顯示資料日、單位、圖例及缺值狀態。
- 圖表下方提供白話解讀與「這不代表什麼」，避免把相關性誤讀成建議。
- 進階數據收進可展開區塊，預設不干擾一般閱讀。

### 3. 產業觀察

- 先依「值得注意、相對穩定、轉弱」分組，再顯示實際排名。
- 每個產業摘要只呈現方向、主要依據與資料日。
- 展開後才顯示成分股、相對報酬、成交與風險明細。
- 不只靠顏色表達強弱，文字標籤與正負號必須並存。

### 4. 個股與 ETF

- 搜尋框成為頁面唯一主動作，提供可理解的代碼／名稱範例。
- 個股首屏依序顯示：標的身分、資料日、價格事實、事件摘要、模型狀態。
- 將「已發生事件」與「五日模型情境」視覺分區，避免使用者混淆。
- 長表格在手機轉為定義列或可控的水平捲動，不隱藏核心欄位。

### 5. 每日報告

每日報告採「摘要可快讀、證據可深挖」的研究文件結構：

1. 報告標題、類型、來源交易日、適用交易日與發布狀態。
2. 三至五點執行摘要。
3. 市場結論及支持證據。
4. 反對證據與失效條件。
5. 產業與異常事件。
6. 模型結果及方法限制。
7. 資料品質、涵蓋率、來源與附錄。

桌面加入頁內目錄；手機使用可收合章節。摘要不得取代原始證據，原始證據也不應阻塞一般投資人的第一屏。

### 6. ASK ABSORB

- 浮動面板定位為「針對目前頁面追問」，自動帶入市場、頁面及標的語境。
- 完整 ASK ABSORB 頁定位為跨市場、跨報告的研究對話。
- 首次開啟顯示三個與目前頁面相關的問題範例，不自動送出。
- 回答固定呈現資料日、依據與限制；不可把無資料回答包裝成確定結論。

### 7. 學習

- 從辭典改成與介面連動的「看懂這個指標」。
- 每個詞條包含：白話定義、如何閱讀、常見誤解、在 ABSORB 哪裡出現。
- 報告與圖表可直接連到對應詞條，但不另建複雜教學系統。

## 六、視覺與內容規則

- 延續白色畫布、深藍識別、細邊界及低裝飾的研究平台氣質。
- 主要內容採繁體中文；英文只保留品牌、必要縮寫與研究標籤。
- 標題使用問題導向語言，例如「今天市場發生什麼？」；專業術語保留在第二層。
- 一般投資人摘要每段控制在二至三行；完整定義與方法移入報告或學習頁。
- 數字採等寬數字格式，單位與期間不可省略。
- 漲跌、警示及資料狀態皆以文字、符號與顏色共同表達。
- 不加入玻璃擬態、黑金風、裝飾性 K 線、促銷式大標語或持續閃爍動畫。

## 七、重要狀態

四種資料狀態必須全站一致：

- **available**：資料可用，顯示明確日期。
- **partial**：部分可用，說明缺少範圍及仍可安全閱讀的部分。
- **stale**：顯示舊資料日期，不使用「現在」或「最新」。
- **unavailable**：不顯示推估值，說明可稍後重試及仍可前往的頁面。

另外需設計 loading、空結果、搜尋錯誤、登入限制及對話服務不可用狀態，避免只處理正常資料畫面。

## 八、響應式與無障礙

- 主要驗收寬度：390×844、768×1024、1440×900、2560×1440。
- 390px 不得出現整頁水平溢出；主要入口須在一次點擊內可達。
- 觸控目標至少 44×44px。
- 支援鍵盤順序、skip link、可見 focus、Esc 關閉浮層及焦點返回。
- 對話面板開啟後限制焦點於面板內，並遵守 reduced motion。
- 圖表提供文字摘要或表格替代內容。
- 200% 縮放後仍可閱讀及操作。

## 九、執行階段

### 階段 1：內容與流程定稿

- 建立各頁資訊清單，標記一般層、研究層及重複內容。
- 確認五個核心入口及 ASK ABSORB／學習的輔助位置。
- 以真實最短、一般與最長內容檢查版面需求。

交付物：站點地圖、內容優先矩陣、主要任務流程。

### 階段 2：低擬真原型

- 先製作今日市場、每日報告與手機導覽三個關鍵原型。
- 使用真實欄位名稱及 fail-closed 狀態，不使用漂亮但不存在的示意數據。
- 邀請一般投資人完成快讀任務，邀請研究者完成證據追查任務。

交付物：桌面／手機 wireframe、任務測試紀錄、修正版資訊架構。

### 階段 3：視覺系統與共用殼層

- 確立字級、間距、狀態、按鈕、表格、圖表及 disclosure 規則。
- 重整桌面側欄、手機五入口導覽、市場切換及 ASK ABSORB 入口。
- 更新 `DESIGN.md`，只記錄已驗證且跨頁共用的規則。

交付物：高擬真首頁、共用元件狀態表、更新後設計規範。

### 階段 4：頁面實作順序

1. 共用殼層與導覽。
2. 今日市場。
3. 每日報告索引與報告明細。
4. 市場、產業、個股。
5. ASK ABSORB 與學習。

沿用 Flask、Jinja、現有 CSS 與原生 JavaScript；除非原生能力確實不足，不新增前端框架或元件依賴。

### 階段 5：驗收與發布

- 自動測試：路由、模板語意、資料狀態、鍵盤控制及不安全 DOM 寫入。
- 瀏覽器驗收：完整任務、桌面／手機、console、network、溢出及焦點。
- 內容驗收：摘要與完整報告的數值、日期、限制和來源一致。
- 發布維持既有 no-traffic、驗證、流量切換及回滾流程；UI 重設不得繞過資料發布契約。

## 十、驗收標準

- 首頁第一個 viewport 同時看得到市場、資料日期、資料狀態、白話結論及主要風險。
- 一般投資人可在 30 秒內說出市場方向、主要依據與資料限制。
- 研究者可從每日報告追到證據、反證、方法與資料品質，不需猜測數字來源。
- 台股／美股切換後，導覽、日期、內容及報告連結使用同一市場語境。
- available、partial、stale、unavailable 四種狀態皆有瀏覽器證據。
- 390px 無整頁水平溢出，浮動 ASK ABSORB 不遮住最後一段內容。
- 鍵盤、觸控與滑鼠皆可完成主要流程；console 無 error 或 warning。
- 不新增虛構數值、不把缺值轉成零，也不降低既有資料驗證門檻。

## 十一、範圍邊界

本次重設不包含：

- 修改量化模型、資料來源、報告發布規則或 GCS 指標。
- 新增即時新聞爬取、交易下單、券商串接或投資建議。
- 改寫歷史 immutable 報告。
- 為了視覺效果新增無法驗證的市場數字。
- 同時導入新前端框架、設計系統套件或複雜動畫層。

## 十二、主要風險與控制

- **過度簡化造成資訊失真**：摘要永遠保留資料日、依據與限制，並提供完整報告入口。
- **專業資料重新塞回首頁**：以每日報告作為深度資訊的主要容器，首頁只保留決策所需摘要。
- **手機導覽再次膨脹**：五個核心入口固定，新增功能先放入內容脈絡或更多選單。
- **新舊頁面視覺不一致**：先完成共用殼層與狀態規則，再逐頁遷移。
- **本機缺資料導致錯誤設計**：使用 production-shaped fixture 驗證各狀態，不以假資料取代正式資料契約。

## 十三、完成定義

計畫完成不等於畫面好看；必須同時滿足：一般投資人看得懂、研究者追得到證據、手機操作完整、資料狀態誠實、既有發布安全不受影響。
